		- creating a task on Feather #[[project elephant]]
		  collapsed:: true
			- Go to feather.openai.com
			- Switch from Start tab > Campaign tab > Project Elephant
			- All task batches (all subject matter domains) > Your subject matter domain
			- Claim a task from "unclaimed" > "In progress" > "Completed" > 1 reviewer will move it to "In Review" > "Needs Work" > shift back to "In progress" to make changes with feedback > "Fixing done" for a second reviewer
				- might go back to "Needs work" > you shift to "In progress" to make changes again > "Signed off" after completing second round of revisions automatically
				- or "Signed off" from second reviewer
			- Create a user message
				- paste task here at the top of the window
				- click create
				- Feather will generate 2 responses. The answer should largely be incorrect by the model either by reasoning, conclusions, etc.
					- If the model is generally correct, the task is not strong enough and should be revised so that the model gets the response mostly incorrect
					- Rewrite the prompt until incorrect responses are generated
			- Scorecard for each response:
				- Click Yes/No for the scorecard.
				- Provide a brief justification for your answer
			- "Continue conversation" > both responses will now be combined / synthesized.
				- copy and paste the task into a "finalized task" box.
				- estimate number of hours to reach this conclusion
			- add rubric items
				- generally has four parts:
					- actual criterion points calculation (negative or positive)
					- boolean statement to analyze the quality of the response (true/false condition)
					- for the reviewer's context: CITATION, QUOTE, SOURCE, JUSTIFICATION
						- source should be a link that the reviewer may copy and paste to verify the information in their own browser.
					- timeliness requirement
						- a date after which no more information can be introduced by the model to answer the task.
				- avoid criteria that will trigger at the same time, will flag as "redundancy issue".
					- example: [+5] includes Source A, [-5] does not include Source A
				- to prevent hallucinations, give an exhaustive list of sources so that the model does not cite dubious or false sources.
				- if constraints are introduced in the task prompt, write a penalty criterion for that
			- avoid "maximum points" field because sometimes scenarios may garner a lot of points for certain aspects but completely lack in other aspects
			- rather than uploading a supporting file for the task materials, you should make a publically available document or sheet as one source (not the ONLY source) for the reviewer
				- if you want to pass information over to OpenAI, then perhaps create a CSV file and upload it.
				- provide any URLS for real memos or outputs aka an article you have published, link how you have tied that article to this task
				-
			- describe your thought process for this task is important. it is very difficult for reviewers to follow your state of mind because the rubric is broken up into criteria.
				- explain your overarching themes, goals, desires for this task and what you want to see in a response. this is more for human readability to understand your motivations and better evaluate your rubric.
			- advance the task to "completed"!
			- you can disregard some of the warnings because they appear in every task (aka the ones about vague prompts.)

		- # PART 3: Reviewing tasks
			- ## Issue categories
			  collapsed:: true
				- ### general
					- general feedback
					- clarification
				- ### major issue
					- #### task prompt issue
						- not timeless
						- not clear
						- not objective — contains "best" or "top" qualifiers
					- #### rubric issues
						- not clear
						- not objective
						- not accurate
						- not self-contained
						- not verifiable without internet access
						- incorrect criterion score - does not accurately reflect relative importance
						- overly restrictive — too limiting and may auto-fail good responses
						- faulty sources - the information for a criterion cannot be found in the source(s) provided
						- redundant - different from "mirror criteria"
						- stacked criteria
						- not timeless
						- major issue — other
				- ### minor issue
					- #### rubric issues
						- minor language, notation, or syntax errors in the criteria
						- criterion is too long / complex
						- minor issue — other
